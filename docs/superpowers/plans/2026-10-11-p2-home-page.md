## 三态降级：**不新增任何组件**（2026-10-11 用户裁定）

原计划要新建一张 `subsystem_status_card.slint`。用户裁定：**P9 逐页对照时，参照没有的组件就是缺陷，不接受。**
spec §5 里的"状态卡"按**行为**理解，不按**新组件**理解。改用参照现有积木表达：

| tier | 渲染 | 用到的参照件 |
|---|---|---|
| `Ready` | 列表，**与参照完全一致** | `DistroList` + `DistroCard` |
| `Partial`（Booting） | 参照自带的加载覆盖层："..." + `main.loading` | `main_view.slint` 的第三个 `if` 分支 |
| `Partial`（Unauthorized / Offline） | 骨架行 + 状态文案 | 推 N 个**空 `Distro` 行**，由参照的 `DistroCard` 自己渲染成占位；`TaskStatusToast` 显示"等待授权 / 连接已中断" |
| `Down`（Stopped / NotInstalled） | `DistroNotFoundView`，文案按态切换 | **链接槽当动作用**：`guide_url` 传 `wsa://com.android.settings`，走参照现成的 `open_url` 回调 ⇒ "启动 WSA"。零新组件 |
| 有上次快照且非 `Ready` | 列表照常渲染 + 整体置灰 + `TaskStatusToast` 标注"数据可能过期" | `DistroCard` 的 opacity、`TaskStatusToast` |
| 任一操作进行中 | `TaskStatusToast` 显示进度文案 | `TaskStatusToast` |

**骨架占位不用新画**：`data.rs` 在 T2 推 N 个字段全空的 `Distro`，参照的 `DistroCard` 就渲染成灰块占位——这是 `DistroCard` 的一种数据状态，不是新组件。

**两处放宽（必须知悉）**：
1. spec §5 原文"T2 …应用网格显示**骨架占位**"与"状态卡显示进度/等待授权"在参照结构下无法同时成立——`DistroNotFoundView` 与列表是 `main_view.slint` 里**互斥的两个分支**。落地取"不空白"这个实质要求：Unauthorized/Offline 走骨架行 + toast 文案；Stopped 走 `DistroNotFoundView`。两者都不空白。
2. spec §5 原文的"'重连'按钮"取消，改为**自动重连**：Task 11 已实现 `probe()` 在条目缺失时自动 `adb connect`，加上 5 秒轮询 = 持续自愈。参照没有重连按钮，新增一个就是缺陷。用户可见的部分是 toast 文案"连接已中断"，以及重连成功后列表自行恢复。

## Task 3 — 应用运行状态探测（`ps -A`）

首页卡片的启停切换（Q22 保留 16 个回调、有对应动作的按钮不隐藏）需要知道**单个应用是否在跑**。参照免费拿到（`wsl -l -v` 有 Running/Stopped 列），我们必须问 Android。

**必要性裁定（2026-10-11 用户：不必要就能接受退化）：判断为必要，保留。**
理由：卡片的主控件就是这个切换。没有逐应用状态，切换永远停在"启动"，P9 对照时参照的卡片写着 `Running`/`Stopped` 而我们没有——那同样是"参照有、我们没有"，按用户裁定属于缺陷。

**三态渲染规则（spec §5，逐条落到字段）：**

| tier | `degraded` | 渲染 | 用到的参照件 |
|---|---|---|---|
| `Ready` | `None` | 列表，**与参照完全一致** | `DistroList` + `DistroCard` |
| `Partial`（Booting） | `LoadingOverlay` | "..." + `main.loading` | `main_view.slint` 第三个 `if` 分支 |
| `Partial`（Unauthorized） | `Skeleton { toast_key: "main.subsystem_unauthorized" }` | 空 `Distro` 行成骨架 + toast | `DistroCard`、`TaskStatusToast` |
| `Partial`（Offline） | `Skeleton { toast_key: "main.subsystem_offline" }` | 同上 | 同上 |
| `Down`（Stopped） | `NotFound { headline_key: "main.subsystem_stopped", action_key: "main.start_subsystem", action_url: "wsa://com.android.settings" }` | `DistroNotFoundView` + **启动链接** | `DistroNotFoundView` 的 `open_url` |
| `Down`（NotInstalled） | `NotFound { headline_key: "main.subsystem_not_installed", action_key: "main.guide_link", action_url: 指引地址 }` | 同上 | 同上 |

- **有 `last_good` 且 `tier != Ready`** ⇒ `rows = last_good`、`greyed = true`、`stale_label_key = "main.stale_data"`。此时 `distros.length > 0`，参照的 `has_error` 为 false ⇒ **列表分支照常渲染**，置灰只是 `DistroCard` 的 opacity——参照结构原生支持，不需要改它
- **任一 op 进行中** ⇒ 所有卡片启停按钮统一置灰 + `TaskStatusToast` 显示 `operation.*`。依据：MAPPING §4.1.2 记录我们是单槽位全局 `active_op`，参照是 per-distro map；executor 本就是全局单闸门，只灰一个反而暗示其他卡片可点
- **`tier == Ready` 且 `fresh` 为空** ⇒ `NotFound { headline_key: "main.no_apps", action_key: "", action_url: "" }`。空 `guide_url` 时参照**本来就不渲染链接**（`if (root.guide_url != "")`），同样零改动

## Review Focus（对抗性复核点）

1. **Ready 态必须与参照逐像素一致**——用户裁定（2026-10-11）"P9 对照时参照没有的组件＝缺陷，不接受"。逐项检查：无新增组件文件、无新增回调名、无新增可见元素。`search_box` 是唯一允许的新增（Q24），且必须已标进 MAPPING
2. **T2/T3 绝不能空白**——本阶段唯一验收。重点看：`refresh_home` 在 `probe()` 失败时是否会清空 `last_good`；`Degraded::NotFound` 是所有空数据情况的兜底分支，`headline_key` 不得为空；参照的 `if (root.guide_url != "")` 保证空链接时只显示文案、不显示悬空链接
3. **启动/重连走 `open_url` 的副作用**——`open::that` 是 fire-and-forget，不拿 `WsaOpGuard`，点完立刻返回。WSA 冷启动 12–17 秒，这段时间首页**必须**仍给出反馈（`TaskStatusToast` 显示"正在启动"），且 `on_home_clicked` 的 manual 路径要立即刷新一次，否则用户会以为点了没反应
4. **4s 防抖会饿死手动刷新**——`should_refresh` 拦截非 manual 触发。`open_url` 触发的启动必须紧接着走 manual 刷新路径，否则 4 秒内点第二下毫无反应，会被当成"按钮坏了"
5. **去重吞掉状态变化**——若 `snapshot_changed` 只比包名，应用 `Running→Stopped` 永远推不下去。这条已有专门测试
6. **`ps -A` 在真机是否可用**——Task 3 的第一步就是真机实测。若不可用，`running_apps` 恒返回空集并记 MAPPING，**不得**让首页因此空白
7. **`slint::include_modules!()` 移动后两个 bin 还各自编译**——`wsadash` bin 不 `mod app;`，不应被 slint UI 牵连；`cargo test --release --bin wsadash` 必须仍是唯一判据
8. **`build.rs` C3 是否真的触发**——改一个 `.slint` 后 `cargo build` 必须重跑 build.rs。这条要**实际验证一次**（改颜色 → 看 exe 时间戳），不能只看代码
9. **`.slint` 里的键拼写**——键扫描测试必须真的跑起来且能红（故意拼错一次确认它会失败）
10. **窗口可见性门控**——`is_visible` 为 false 时轮询停止，但点"启动 WSA"后子系统要 12–17 秒才 Ready，用户若此时切走窗口，回来后状态可能陈旧。确认 manual 刷新路径能救回来
11. **单槽位 busy 的全局置灰**——确认在 op 进行中，所有卡片按钮都禁用，且 toast 显示 busy 文案；op 结束后必须恢复（`Drop` 同步清槽，Task 12 已测）
