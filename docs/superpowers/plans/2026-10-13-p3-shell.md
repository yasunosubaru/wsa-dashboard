## 0. 先解决 P2 留下的一处可见缺陷

P2 的截图里"停止"按钮显示为**豆腐块**。P2 当时记成"本机没装 Segoe Fluent Icons"，
**那个结论是错的**，本计划 Task 1 把它改掉。

真相：参照 `components/common.slint:5` 有 `import "../../../assets/font/icons.ttf";`，
而那个 ttf 读出 name 表是 **微软 Segoe Fluent Icons v1.47 的子集**
（family 名 `Segoe Fluent Icons`，© 2025 Microsoft Corporation）。
`theme.slint` 写死这个 family 名，靠的就是这行 import 把它注册进 Slint 字体库。
**参照自带字体，因此不依赖系统装没装。** 我们没搬这行，于是落到系统字体，本机没有 → 豆腐块。

顺带确认：旁边的 `assets/font/segoeicons.ttf`（462 KB）参照**没有任何文件 import**，是死资源，**不搬**。

## 1. P9 约束下的一个真问题：九个页签里只有一个页存在

参照 `sidebar.slint` 每个条目都有 `show_*` 开关，入参来自 `app.slint` 的
`in-out property <bool> sidebar_add: true;` 等九个属性，由设置页持久化（`save_sidebar_state()`）。

所以 P3 **不发明新机制**：把还没做的八个页签对应的 `show_*` 置 `false`，
每做完一页翻成 `true`。这是参照自己就有的通路，不是新增组件、不是新增属性。
记入 MAPPING（P3 期间侧栏只有 2 个可见条目：home + settings 占位除外）。

**settings / about 页是 P6**。P3 侧栏只有 **home** 一个可用条目。
其余八个 `show_*: false`。侧栏因此只剩：折叠按钮 + home + 底部 settings（settings 也要等 P6，
所以 P3 连 settings 也 `false`）。→ **P3 侧栏只有折叠按钮 + home。**

这一点要在验收截图里说清楚，并且写进 MAPPING §8：它不是缺陷，是"页还没做"，
且关闭每个开关的通路与参照完全一致。

## 3. 两处需要提前想清楚的地方

### 3.1 无边框 + 透明背景会打破截图脚本的判色

`capture.ps1` 现在用**众数颜色**当"这是页面而不是一块空白"的判据
（`-ExpectedBackground`，默认 `#FFFFFF` = `Theme.content_bg`）。
参照的窗口是 `background: transparent` + `border-radius: 8px`，角落因此是**透明**的，
PNG 里会是 alpha；圆角外那一圈也会让众数不再是纯白。

Task 5 之后必须改判据，否则四张图全部会被自己的检查拒掉。改法（Task 5 内做）：
先合成到白底再判色（`Graphics` 画一个白矩形再画 `PrintWindow` 的结果），
`#FFFFFF` 这个期望值因此仍然成立——**合成后的底就是用户看到的窗体底色**。

### 3.2 折叠状态不持久化是 P3 的正确范围

参照 `toggle_collapsed` → `save_sidebar_state()` → 配置。spec §10 把"配置与迁移"放在 **P8**，
P6 才有 `ConfigManager`。所以 P3：`sidebar_collapsed` 是 `AppWindow` 上的 `in-out` 属性
（会话内有效），`toggle_collapsed` 回调接一个**记日志的空实现**并注明 P8 接上。
这与参照的层次划分一致，不是漏做。

## 4. Review Focus（写完计划时先列在这里，做 task 时逐条对着看）

1. ~~豆腐块到底是不是字体问题——Task 1 完成后 `p2-ready.png` 里 `\u{E769}` 必须变回图标。~~
   **没做到，且不是移植能修的**：Task 1 补齐了参照的 `import` 和 ttf 本身，字形确实在子集里、
   name 表对得上、GDI 能加载、写盘后 `AddFontResourceExW(FR_PRIVATE)` **调用成功**——
   图标**仍是豆腐块**。Slint 的 Skia 后端走 DirectWrite，而 DirectWrite 的系统字体集合独立于
   GDI 字体表，内嵌字体和进程私有注册的字体都到不了它。参照全 `src` 没有任何运行期字体注册、
   renderer feature 与我们逐字相同 ⇒ **参照在同一台机器上表现一致**。
   唯一能落地的动作是装 Segoe Fluent Icons。详见 MAPPING §9。
2. 侧栏折叠宽度必须是 54/200 两个值，且展开动画 200ms（参照 `animate width`）。✅ 54px 已验，
   `p3-sidebar-collapsed.png` 中为 81px（×1.5）。
3. 页签切换**不得**用 `if` 条件销毁：参照用 opacity + x:10000px，页内状态要保住。✅
4. 九条目里八个 `show_*: false` 的通路必须和参照一模一样（属性名、类型、默认值），
   否则 P4–P7 翻开关时会发现接不上。✅（10.2）
5. mail 徽标保留但默认不可见——不许删，删了就是 P9 说的可见差异。✅（10.4）
6. ~~无边框窗口的拖动必须走 `start_drag()`，不能在 Rust 里自己 `set_position`。~~
   **这条是错的**。`start_drag()` 会把鼠标事件交给操作系统吞掉，标题栏 `TouchArea` 的 `moved`
   此后不再触发。参照 `handlers/window.rs:51-59` 就是 `set_position(pos + delta)`，
   而且参照的 `TitleBar` 报的是相对按下点的位移，窗口跟着光标走会让它回到常量附近，
   累加式 `pos + delta` 因此不发散。**照抄参照**。详见 MAPPING §10.5。
7. ~~截图脚本的判色必须在 Task 5 里一起改，否则后面的截图全部被自己的检查拒掉。~~
   **亮色其实不用改**（`#FFFFFF` 仍成立），真正被拒的是深色态，解法是给那次运行传
   `-ExpectedBackground '#2D2D30'`——而且首次报错把"主题变了"误判成 f.lux 染色，
   文案已按两种可能分开。判色本身没问题，问题在报错。
